# Windows 外部键盘回归，2026-09-27

## 环境与测试路径

- Windows 10，游戏窗口 1444×824，最终 EditorPlus **0.4.32.0**。
- 使用安装在此机的微软拼音，不伪造组合字符串。
- 用户明确同意前台键鼠控制；`cua-driver` 以 `delivery_mode=foreground` 向确切 PID/HWND 投递系统输入。
- 每个动作都有前后窗口截图、驱动返回值、游戏内只读状态快照。测试作品全部在输出目录，不操作玩家作品/存档。
- 不是实体键盘手工测试，也不把驱动的 `unverifiable` 返回当作成功；以游戏实际文字、历史、选中对象和落盘结果判定。
- 不改变系统剪贴板，不改默认输入法，不上传或发布。

## 发现与修复

1. **0.4.30：正文失焦后的快速 Ctrl+Z 没有反应。**
   输入框的窗口事件可以响应，但 `Keyboard.wasPressedThisFrame` 没有报告这些短按。
   0.4.31 增加未聚焦时的窗口 KeyDown 处理，复用快捷键的同帧去重、弹窗/剧情图隔离和组合输入检查。
2. **普通正文刚提交就切 CG，隐藏输入框仍是旧正文。**
   例如普通正文保存了末尾的“你”，CG 框还缺这个字。0.4.32 在正文提交后无通知同步另一种输入框，双向验证通过。
3. **测试观察器在关闭剧情图后遇到 Unity 已销毁的焦点引用。**
   `?.name` 不识别 Unity 假 null，状态文件停止更新。这是观察器错误，不是一次游戏撤销失败。
   已改用 Unity 对象判空；驱动脚本也拒绝 sequence 未更新的状态。整句删除的恢复随后通过真实 Ctrl+Z 和新状态复核。
